## 依赖检查

使用 npm 官方 registry 执行完整审计，包含开发依赖。已更新 `fflate` 至 0.8.3，限定 `get-uri` 使用 `basic-ftp` 6.2.2、`@prisma/config` 使用 `deepmerge-ts` 8.0.0；后端与 Agent 的 Vitest 更新至 5.0.3。Prisma 仍固定 6.19.3，已验证客户端生成与普通配置加载。覆盖依赖的原因如下：

| 依赖 | 问题与处理 |
| --- | --- |
| fflate | [ZIP64 异常归档可导致死循环](https://github.com/advisories/GHSA-px8p-9vwx-vf98)，升级到修复版本 |
| basic-ftp | [目录列表解析可导致 CPU 拒绝服务](https://github.com/advisories/GHSA-c475-qrg2-pj4r)，限定传递依赖到修复版本 |
| deepmerge-ts | [递归对象合并可耗尽调用栈](https://github.com/advisories/GHSA-ggr8-5vv4-36mx)，限定配置工具依赖到修复版本并检查普通对象合并 |
| Vitest / tinypool | [文件读取问题](https://github.com/advisories/GHSA-82fw-gwwq-j7x9)与[原型污染风险](https://github.com/advisories/GHSA-5gmw-xhrv-c9v3)，升级测试工具并重跑测试 |

剩余告警：后端的 `node-forge` 1.4.0 及其父依赖 `@neteasecloudmusicapienhanced/api`，npm 显示两项 high，来源是同一个 [RSA 签名验证问题](https://github.com/advisories/GHSA-86w9-cpqp-85rv)，上游尚无已发布补丁。当前适配器调用上游请求加密，`util/crypto.js` 仅使用固定公钥加密与字节转换，未使用存在问题的 RSA 签名验证接口。这是对当前调用范围的核查，不代表该依赖已修复；新增验签功能或升级上游后须重新评估。前端、Agent 与根目录审计无告警。

## 验证边界

MySQL 测试覆盖表结构与存储行为，不替代目标服务器真实数据库连接与数据备份。音源完整性验证不保证平台接口始终可用，也不会将会员试听当作完整歌曲。声卡切换、实际音质、NapCat 在线状态、Linux 网络与第三方安装速度应在部署环境验证。

源码包只收录公开示例配置。凭证检查能发现已知本机凭证和常见私钥 / Token 格式，不能代替发布前人工检查；生产日志、缓存、数据库和设备配置不属于源码。
